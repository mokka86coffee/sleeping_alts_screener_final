# Скринер спящих альткоинов

Система ищет монеты, которые долго стояли, и ловит момент, когда в них
приходит движение. Прогон собирает метрики по выборке, прогоняет их
через детекторы и правила, и выдаёт три вещи: страницу с залом и
карточками, отчёт в мессенджер и запись в журналы.

**Стек.** Python считает, чистый JavaScript рисует. Фронтенд-фреймворка
нет: страница собирается генераторами в один самодостаточный HTML и
кладётся на GitHub Pages.

## Как устроен прогон

Порядок восстановлен по зависимостям и по тому, что делают модули.

**1. Сбор.** `core_binance` и `sources_*` приносят свечи, фандинг,
открытый интерес и внешние срезы. `analytics_metrics` сводит их в
снимок по монете: сырые числа плюс форматированные значения.

**2. Признаки.** По снимку считаются индикаторы, уровни, карта
ликвидаций, интрадей-слой, пульс-детекторы. Каждый — отдельный модуль,
и почти все они листья: ничего не тянут, только считают.

**3. Кандидат.** `analytics_candidate` связывает метрики, детекторы,
скоринг, вето и стратегию в один объект.

**4. Решение.** `analytics_action` говорит, что делать с монетой
сегодня; `analytics_size` — каким размером; `analytics_exit` — когда
пора смотреть на выход. Разрешение рынка приходит отдельно из
`analytics_permission`.

**5. Сборка экранов.** `analytics_stars` собирает данные для зала и
карточек — один расчёт на два экрана. Это самый связанный модуль
проекта: тянет семнадцать других.

**6. Отрисовка.** Генераторы `render_*` превращают данные в HTML.

**7. Память.** Пульс, журналы решений и предположений пишутся на диск,
чтобы следующий прогон видел прошлые.

## Модули аналитики

### Данные и признаки

**`analytics_metrics`** — сбор метрик по монете: сырые числа плюс
форматированные значения. Опора для четырёх модулей, сам тянет пять.
Здесь живёт снимок, из которого потом читают все остальные.

**`analytics_indicators`** — технические индикаторы, чистые функции без
сетевых вызовов. Восемнадцать функций, никаких зависимостей — на него
ссылаются трое.

**`analytics_pulse`** — показания монет: рабочее окно неделя плюс архив
тридцать дней. Самый востребованный модуль проекта, к нему обращаются
пять других. Именно он даёт историю, без которой детекторы не работают.

**`analytics_levels`** — поиск структурных уровней: сопротивления,
поддержки, границы диапазона. Отсюда приходят потолок и опора в
карточке.

**`analytics_liqmap`** — модельная карта ликвидаций: кластеры плеча,
посчитанные из одних свечей, без внешних источников.

**`analytics_intraday`** — что происходит с монетой прямо сейчас.
Крупнейший модуль после звёзд и лидеров, двадцать четыре функции.

**`analytics_momentum`** — момента-величины, общие для карточки, зала,
орбиты и отчёта. Вынесены отдельно, чтобы четыре потребителя считали
одно и то же одним кодом.

### Детекторы и правила

**`analytics_squeeze`** — пульс-детекторы топлива: заряд, разряд,
перегрев, поглощение. Здесь же расчёт усилия против результата и тест
Вайкоффа.

**`analytics_flow`** — отбор, порядок и ключи семейства FLOW для
потребителей отчёта.

**`analytics_permission`** — разрешение рынка и индекс альтсезона. Тянет
календарь, метрики, пульс и резервуар: решение о том, торгуем ли мы
вообще сегодня, собирается из четырёх независимых источников.

**`analytics_reservoir`** — гейт стейблкоинов: вышел ли капитал из
обороны.

**`analytics_calendar`** — календарь событий рынка. Частокол, который
видно заранее, — из него берётся вето на вход перед событием.

**`analytics_unlocks`** — разлоки токенов: ручные данные о том, когда в
рынок придёт предложение.

**`analytics_demand`** — структурный спрос, обратная сторона разлоков:
выкупы, стейкинг, регулируемые обёртки.

**`analytics_link`** — связка разлока и открытого интереса. В
докстринге прямо сказано: отметка, а не вердикт.

**`analytics_scoring`** — скоринг монеты, где каждое слагаемое именовано
и сохраняется отдельно.

### Решения и деньги

**`analytics_action`** — действие вместо вердикта: что делать с монетой
сегодня. Восемнадцать веток решения плюс общий разбор возражений,
который прикладывается к любой из них.

**`analytics_size`** — размер позиции как правило, а не как привычка.

**`analytics_exit`** — правило выхода. Говорит «пора смотреть», а не
«продавай».

**`analytics_strategy`** — построение торгового плана: уровни входа,
стопа и целей.

**`analytics_portfolio`** — два подхода к одним монетам: HOLD и
трейдинг.

**`analytics_candidate`** — сборка кандидата, связывает метрики,
скоринг и стратегию.

### Память системы

**`analytics_decisions`** — журнал решений. В докстринге сформулировано
точно: записывать не только монеты, но и себя.

**`analytics_actionlog`** — журнал предположений: что стратегия сказала
и когда. Без него нельзя проверить, сбывалось ли сказанное.

**`analytics_leaders`** — отслеживание двух выборок: лидер прогона и
аномальные объёмы. Второй по величине модуль.

**`analytics_manual_fields`** — поля журнала, которые код узнать не
может. Явное место для того, что вводится руками.

### Внешние срезы

**`analytics_coinglass`** — перекос ликвидаций по монете, чтение
готового среза без сети.

**`analytics_hyperliquid`** — перекос китов, тоже чтение готового среза.

**`analytics_flatwatch`** — мост к пузырь-боту: список монет во флэте у
дна.

### Сборка экранов

**`analytics_stars`** — данные для карты долгостроя, один расчёт на два
экрана. Тянет семнадцать модулей — это узел, через который проходит всё.

## Отрисовка

**`render_podium.py`** — главная страница: ворота с залом-списком,

**`render_flow_report.py`** — отчёт по семейству FLOW.

## Что стоит знать, читая код

**Комментарии объясняют «почему», а не «что».** В коде много мест, где
рядом с правкой записана история дефекта: что было не так, чем это
оборачивалось на экране и почему выбрано именно такое решение. Это не
многословие — без причины правку через месяц снимут обратно.

**Отсутствие данных не должно становиться выводом.** Правило появилось
дорогой ценой: расчёт усилия читал поле, которого нет в снимке, получал
ноль и выдавал «истощение хода» вместо «поглощения» — перевёрнутый
вердикт. Теперь пустой источник даёт пусто, и карточка рисует прочерк.

**Одно значение на всех — всегда дефект.** Второй цикл сборки звёзд не
переприсваивал переменные, и уровни, тест Вайкоффа и ожидание журнала
у всех пятидесяти двух монет приходили от одной. Значения выглядели
правдоподобно, поймать это можно было только сравнением между монетами.
В конце сборки стоит сторож, который считает число различных значений
по каждому полю и предупреждает, если личное поле оказалось общим.

**У каждого числа есть окно.** Один и тот же относительный объём даёт
разные ответы на дневном, трёхдневном и десятидневном масштабе.
Сравнивать можно только величины одного окна — иначе квартальный
индикатор ответит на недельный вопрос, и ответ будет неверным.

**Признак, одинаковый у обоих исходов, ничего не разделяет.** Прежде
чем вводить правило, стоит проверить его на архиве: отличает ли оно
вышедшие в плюс от вышедших в минус, или встречается одинаково часто у
тех и других.

## Датчики, которых нет

Найдены 25 августа, ни один не реализован.

**Состояние листинга — реализован 25 августа, `analytics_listing.py`.**
Делистинг важнее разлока: транш даёт навес, который цена может
переварить, а делистинг убирает сам стакан, и позицию закрывают
принудительно по чужой цене.

Читается машинно, но **каждая площадка сообщает по-своему**, и общего
поля нет. Binance меняет `deliveryDate` у бессрочного с заглушки две
тысячи сотого года на реальный срок — в тот же момент, когда выходит
объявление. Bybit держит статус и время поставки в справочнике
инструментов. OKX при делистинге просто убирает инструмент из выдачи.
По BingX эндпоинт не сверен и в код не поставлен.

Поэтому сверху лежит **сравнение со снимком**: единственный способ,
работающий везде, потому что поля у всех разные, а исчезновение
инструмента выглядит одинаково. Он же ловит аварийный делистинг, у
которого предупреждения нет вовсе. С защитой от сбоя: если пропала
треть списка, это отказ сети, а не рынок, и датчик молчит.

**Сроки предупреждения различаются в разы** — от суток у Binance до
недели у OKX и считаных часов у мелких площадок. Значит опрашивать
надо часто, а для монет, живущих только на мелких площадках, времени
мало по существу, и это учитывается размером позиции.

Более ранняя ступень — наблюдательная метка биржи: ещё не решение, но
предупреждение по объёму, ликвидности или активности разработки. Метку
снимают, если проект выправляется.

Слепое пятно: только Binance. Корейские площадки объявляют своими
сроками, обычно позже, и в API это не видно.

**Захват управления через голосование.** Протокол Term Finance потерял
восемь с половиной миллионов: злоумышленник ничего не ломал — скупил
токены управления, провёл своё предложение и легально проголосовал за
передачу себе средств. Ни эксплойта, ни уязвимости в коде.

Для нас это слепое пятно: на графике такая скупка выглядит как
обычное накопление, и скринер пометит её как основание. Рядом со
взломом и неучтённой эмиссией нужна отдельная строка — для монет с
ликвидным токеном управления и тонкой капитализацией.

**Концентрация обращающегося предложения.** У нас есть навес по датам
— разлоки. Нет навеса по владению: сосредоточено ли уже обращающееся
в нескольких связанных руках. У BLESS флоат восемнадцать процентов и
дат нет вовсе; знать, кому принадлежат эти восемнадцать, важнее, чем
знать график.

Инструмент для этого существует (см. `SOURCES.md`), и его лестница
долей почти совпадает с нашей по разлокам — независимое подтверждение
порога.

**Относительная сила против биткоина.** Скринер меряет ход в долларах.
Монета, прибавившая пятнадцать процентов при рынке, выросшем на
двадцать два, попадает в лидеры — хотя она отстаёт. Дважды за день это
переворачивало вывод на противоположный.

## Открытые вопросы

Накоплены за работу, ни один не закрыт.

**Замеры, которые считаются из имеющегося и ничего не меняют в
поведении:** размер позиции против исхода по архиву; возраст хода
против его типичной длительности; относительная сила против биткоина
на входе; связь длины отрицательного ряда фандинга с последующим
движением.

**Дыры в данных:** у тридцати шести монет журнала есть запись о
разлоках, но нет дат; два масштаба объёма из трёх пусты у всех монет.

**Нерешённое в правилах:** размер остаётся полным при окне рынка три из
семи — связаны ли эти величины вообще; в журнале нет правила взять
часть прибыли, есть только выход целиком и хедж.
