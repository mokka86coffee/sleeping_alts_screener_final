# Вспышка следа и мёртвая пауза на входе

Правки в `render/cardscene.py`, **поверх** патчей 2, 3, 4, 6 и 7.
Две штуки, обе про время.

---

## 1 · след набирает силу вместе с подъёмом — `render/cardscene.py`

След предыдущей монеты рисовался в ветке покоя, а она включается
только когда переход уже кончился. Получалось, что в самом последнем
кадре к готовым столбам разом добавлялась ещё одна копия — и это
читалось как вспышка яркости у столбов, которые уже закончили расти.

Теперь след живёт в той же ветке, что и подъём, и набирает силу тем же
множителем. К концу перехода он уже на месте, добавлять нечего.

### Было

```python
      if (from !== to && out < 1) drawSet(g, prepare(from), sinkF(prepare(from), out));
      drawSet(g, prepare(to), riseF(prepare(to), inn));
```

### Стало

```python
      if (from !== to && out < 1) drawSet(g, prepare(from), sinkF(prepare(from), out));
      /* След набирает силу вместе с подъёмом. Раньше он появлялся
         только в самом последнем кадре перехода — и это читалось как
         вспышка яркости у столбов, уже закончивших расти. */
      if (from !== to) drawSet(g, prepare(from), prepare(from).map(() => 1), .13 * inn);
      drawSet(g, prepare(to), riseF(prepare(to), inn));
```

## 2 · вход начинается со второй половины перехода — `render/cardscene.py`

Вход шёл тем же переходом с самого начала, но первая половина — это
утопление предыдущей монеты. На входе тонуть нечему, поэтому зритель
почти две секунды смотрел на пустую воду и ждал, пока дойдёт очередь
до подъёма.

Ставим время сразу на точку подмены: содержимое даётся без задержки,
столбы поднимаются с первого кадра.

Порядок вызовов внутри важен: сначала гряда и композиция, только потом
содержимое. Подписи столбов встают по `colGeom`, а заполняет его
`compose`. Если позвать `applyCard` раньше, `colGeom` пуст, и все пять
подписей садятся в одну точку по запасному значению — нижние блоки
съезжаются в один. Вход занимает 2.7 секунды вместо
4.65, и ожидание перед первым содержимым — ноль вместо почти двух
секунд.

### Было

```python
    /* Первый заход из зала. Прежде карточка возникала целиком и сразу,
       без единого движения, — а потом при первом же листании вдруг
       оказывалась живой. Теперь вход идёт тем же переходом, только
       уходить нечему: from и to совпадают, поэтому фаза утопления
       пропускается сама, и остаётся один подъём из воды. */
    cur = from = to = IDX; tp = 0; swapped = false;
    lay.classList.add('out');
    root.classList.add('moving');
    buildBG(CARDS[IDX].price, CARDS[IDX].entry);
    compose();
```

### Стало

```python
    /* Первый заход из зала идёт тем же переходом, но начинается сразу
       со второй половины. Первая половина — это утопление предыдущей
       монеты, а на входе тонуть нечему: при tp = 0 зритель просто
       две секунды смотрел на пустую воду. Ставим время на точку
       подмены, содержимое даём сразу, и остаётся один подъём. */
    cur = from = to = IDX; tp = .42; swapped = true;
    root.classList.add('moving');
    /* Сначала гряда и композиция, только потом содержимое: подписи
       столбов встают по colGeom, а его заполняет compose. Вызвав
       applyCard раньше, мы получаем пустой colGeom — и все пять
       подписей садятся в одну точку по запасному значению. */
    buildBG(CARDS[IDX].price, CARDS[IDX].entry);
    compose();
    applyCard(CARDS[IDX]);
```
