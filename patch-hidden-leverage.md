```python
    @property

```

### стало

```python
    @property
    def base(self) -> list[Bar]:
        """Базовый ряд. Имя, под которым его читают подкейсы."""
        return self.by_scale.get(1) or self.bars

    def reject(self, subcase: str, reason: str) -> None:
        """Записывает причину отказа и возвращает None.

        Возврат именно None, а не объект с флагом: контракт подкейса —
        SubcaseSignal либо None, третьего состояния диспетчер не знает.
        Поэтому вызов стоит в форме `return ctx.reject(...)` — отказ и
        его причина фиксируются одним выражением, и забыть записать
        причину, оставив голый `return None`, физически труднее.

        Первая запись побеждает: подкейс выходит на первом же
        несовпадении, и именно оно — настоящая причина. Затирать её
        поздними проверками было бы враньём о порядке.
        """
        self.notes.setdefault(subcase, reason)
        return None
```

**Почему метод, а не запись в словарь на месте.** Восемь вызовов в
hidden и семь в spring уже написаны под эту форму — модули писались под
существующий, но не реализованный интерфейс. Дописывается ядро, а не
переписываются подкейсы.

# Блок 4 · `detectors/flow_leverage.py` → интервал фандинга

Это не «ещё одна правка», а предусловие: пока APR считается неверно,
калибровать пороги блока 3 бессмысленно — они окажутся привязаны к
искажённой шкале.

`_to_apr` жёстко берёт восемь часов, при том что его же докстрока
объясняет, почему так делать нельзя: «0.01% за восемь часов и 0.01% за
час — принципиально разные вещи». У части фьючерсов Binance интервал
четырёхчасовой; для них APR занижен ровно вдвое, и монета с настоящим
перекосом −40% APR прочитается как −20% и не пройдёт ступень
`LEV_FUNDING_EXTREME_APR`. Интервал при этом выводится из данных,
которые уже пришли: `fundingTime` соседних записей.

## В `_funding_state`, после разбора ставок

### было

```python
     if len(rates) < 6:
         return None

     aprs = [_to_apr(r) for r in rates]
```

### стало

```python
     if len(rates) < 6:
         return None

     # Интервал выплат берём из самих данных, а не из допущения.
     # У части контрактов он четырёхчасовой, и на них зашитые восемь
     # часов занижают APR ровно вдвое — то есть настоящий перекос
     # читается как средний и не проходит ступени скора.
     # Медиана, а не разность крайних: в истории бывают пропуски и
     # смена интервала биржей, и одна дыра сдвинула бы оценку.
     times = []
     for item in raw:
         try:
             times.append(float(item["fundingTime"]))
         except (KeyError, TypeError, ValueError):
             continue
     gaps = [
         (times[i] - times[i - 1]) / 3_600_000.0
         for i in range(1, len(times))
         if times[i] > times[i - 1]
     ]
     interval_h = _median(gaps) if len(gaps) >= 3 else 8.0

     aprs = [_to_apr(r, interval_h) for r in rates]
```

величина была видна в фактах сигнала, а не только влияла молча.

# Что осталось нерешённым

**Гейт `LEV_FUNDING_HOT_APR` не может сработать.** В `detect` идут
подряд:

```python
    if fund["median_apr"] >= LEV_FUNDING_HOT_APR:   # положительный
        return None
    if fund["median_apr"] > LEV_FUNDING_NEG_APR:    # отрицательный
        return None
```

Второе условие строго шире первого: любой APR, прошедший первый порог,
отсекается вторым. Разграничение с `detect_squeeze` существует как
комментарий, но решения не принимает. Это не ошибка поведения — фигура
всё равно отбрасывается, — но константа выглядит работающей и при
следующей правке порядка проверок может ввести в заблуждение. Либо
убирать, либо переносить туда, где она что-то решает.

**Значения блока 3 требуют прогона, а не обсуждения.** Предлагаю так:
поставить их вдвое мягче написанного (`NEG_APR = 0.0`,
`NEG_SHARE_MIN = 0.4`, `OI_GROWTH_MIN = 0.05`, `PRICE_FLAT_PCT = 20`),
прогнать `flow_probe.py` один раз, посмотреть распределение
`funding_apr`, `neg_share`, `oi_growth` по сработавшим и только потом
затянуть. Иначе повторяется история churn: пороги выше рыночного
максимума, ноль срабатываний, калибровать не на чем.
