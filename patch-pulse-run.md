# Пульс: запись показаний в прогоне

Новый модуль `analytics/pulse.py` — отдельным файлом, он приложен.
Здесь только вызов: две правки в `run.py`.

Модуль хранит показания всей выборки за последние двое суток и отдаёт не
уровни, а изменения. Карточка сравнивала числа сами с собой: «покупка
1.4» без «час назад была 3.1» не значит ничего, и между прогонами
сравнивать было не с чем.

Вызов стоит рядом с `update_leaders` по той же причине, по какой там
стоит журнал: у кандидатов уже посчитаны метрики, сеть не нужна, а
публикация ещё впереди — файл уедет в git этим же прогоном, а не
следующим.

---

## 1 · импорт модуля — `run.py`

### Было

```python
from analytics.leaders import update_leaders
```

### Стало

```python
from analytics.leaders import update_leaders
from analytics import pulse
```

---

## 2 · запись пульса рядом с журналом — `run.py`

Пишем по ВСЕЙ выборке, а не по лидерам. Монета попадает в журнал ровно в
тот момент, когда её карточку смотрят впервые, и без предыстории эта
карточка окажется без единой дельты — то есть без ответа на вопрос, ради
которого её открыли.

### Было

```python
    flow_leaders_path, anomaly_path = update_leaders(candidates, snapshot)
    log(f"→ Лидер FLOW: {flow_leaders_path}")
    log(f"→ Аномальные объёмы: {anomaly_path}")
```

### Стало

```python
    flow_leaders_path, anomaly_path = update_leaders(candidates, snapshot)
    log(f"→ Лидер FLOW: {flow_leaders_path}")
    log(f"→ Аномальные объёмы: {anomaly_path}")

    # Пульс: показания всей выборки за последние двое суток. Рядом с
    # журналом и по той же причине — здесь у кандидатов уже посчитаны
    # метрики, сеть не нужна, а публикация ещё впереди.
    #
    # Пишется по ВСЕЙ выборке, а не по лидерам: монета попадает в журнал
    # ровно в тот момент, когда её карточку смотрят впервые, и без
    # предыстории эта карточка окажется без единой дельты — то есть без
    # ответа на вопрос, ради которого её открыли.
    log(f"→ Пульс: {pulse.record(candidates)}")
```
