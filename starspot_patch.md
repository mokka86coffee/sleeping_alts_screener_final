# Раскладка звёзд: убрать ряды

Одна функция в `render/orbit.py` — `starSpot`. Три правки внутри неё
плюс одна константа перед ней.

---

## 1 · Границы поля

Вставить перед `function starSpot`, сразу после `var PLACED = [];`.

Границы вынесены из проверки наверх, потому что теперь по ним идёт
сама выборка, а не только отбраковка. Держать их в двух местах значит
однажды поменять одно и забыть второе.

### стало

```javascript
  /* Поле, в котором вообще могут стоять звёзды. Значения те же, что
     стояли в проверке ниже, но теперь это ещё и область выборки. */
  var SKY = { x0: 95, x1: 905, y0: 100, y1: 479 };
```

## 2 · Выборка точки

Начало цикла в `starSpot`.

### было

```javascript
  function starSpot(sym, idx) {
    var h = hash(sym);
    for (var k = 0; k < 60; k++) {
      var a = ((h >>> (k % 8)) % 3600) / 3600 * Math.PI * 2;
      var rr = 0.28 + ((h >>> ((k + 3) % 12)) % 1000) / 1000 * 1.05;
      var x = CX + Math.cos(a) * RX * rr;
      var y = CY + Math.sin(a) * RY * rr * 1.35;
      var band = Math.abs(rr - 1);
```

### стало

```javascript
  function starSpot(sym, idx) {
    var h = hash(sym);
    for (var k = 0; k < 60; k++) {
      /* Точка берётся прямо из прямоугольника кадра, а не как угол на
         эллипсе. Прежняя выборка была равномерной по УГЛУ, а не по
         месту, и это давало горизонтальные ряды: у сплюснутого эллипса
         dy/da обращается в ноль на верхней и нижней точках, поэтому
         широкий диапазон углов там укладывается почти в одну высоту.
         При RX = 372 против RY * 1.35 ≈ 200 сгущение неизбежно при
         любом наборе тикеров — дело не в хешах. */
      var x = SKY.x0 + ((h >>> (k % 8)) % 1000) / 1000 * (SKY.x1 - SKY.x0);
      var y = SKY.y0 + ((h >>> ((k + 3) % 12)) % 1000) / 1000 * (SKY.y1 - SKY.y0);

      /* Полоса орбиты теперь считается ОТ точки, а не задаёт её:
         единица — само кольцо, band — отклонение в любую сторону. */
      var rr = Math.hypot((x - CX) / RX, (y - CY) / (RY * 1.35));
      var band = Math.abs(rr - 1);
```

## 3 · Радиус вокруг узлов

Там же, в проверке `nearNode`.

Кадр стал ниже (563 вместо 640), а радиус остался прежним — семь
кругов по 128 съедают заметно большую долю неба, чем раньше, и при
прямоугольной выборке это чаще упирается в исчерпание попыток.

### было

```javascript
        if (Math.hypot(np.x - x, np.y - y) < 128) { nearNode = true; break; }
```

### стало

```javascript
        if (Math.hypot(np.x - x, np.y - y) < 104) { nearNode = true; break; }
```

## 5 · Запасная раскладка

Хвост `starSpot`.

Прежняя выдавала себя мгновенно: шесть звёзд в ряд с равным шагом —
это самая заметная решётка из возможных, и попадала она туда как раз
в тесных прогонах, когда звёзд много. Золотой угол разбрасывает без
периодичности.

### было

```javascript
    /* Место не нашлось: раскладываем по запасной дуге с шагом от индекса,
       иначе все «лишние» звёзды сели бы в одну точку друг на друга. */
    var fb = { x: 120 + (idx % 6) * 130, y: 130 + Math.floor(idx / 6) * 46 };
```

### стало

```javascript
    /* Место не нашлось. Раскладываем по золотому углу: шаг 2.39996
       радиан не укладывается ни в какую долю оборота, поэтому точки
       не выстраиваются в лучи и кольца — сетка 6 в ряд выдавала себя
       мгновенно. Радиус берём заведомо снаружи кольца и зажимаем в
       границы поля. */
    var ga = idx * 2.39996;
    var fr = 1.22 + (idx % 3) * 0.16;
    var fb = {
      x: Math.min(SKY.x1, Math.max(SKY.x0, CX + Math.cos(ga) * RX * fr)),
      y: Math.min(SKY.y1, Math.max(SKY.y0, CY + Math.sin(ga) * RY * 1.35 * fr))
    };
```

## Чего ждать

Звёзды разойдутся по всей высоте кадра, включая полосы над и под
лентой, где раньше их не было вовсе. Верхняя треть разгрузится.

Что стоит проверить: не начали ли звёзды чаще попадать в запасную
раскладку. Признак — несколько штук по дуге снаружи кольца с
одинаковым характером расстановки. Если так, понижай радиус узлов
(п. 3) со 104 до 88: он самый дорогой из трёх фильтров по площади.

Не тронул: `tooClose` (78), `inCard`, порог `band > 0.18`. Они
отвечают за читаемость подписей, а не за распределение, и менять их
вместе с выборкой значит потом не понять, что подействовало.
